# مركز قيثارة داود — تطبيق الويب

تطبيق عربي باتجاه RTL لإدارة النزلاء والإقامات، مبني بـ Next.js وTypeScript.
قاعدة البيانات المقترحة هي PostgreSQL عبر Neon من Vercel Marketplace.

## ما تم إنجازه

- **Sprint 1:** قائمة النزلاء، البحث والتصفية، ملفات النزلاء، الإضافة والتعديل
  والأرشفة، تسجيل الدخول والمغادرة، والغرف.
- **Sprint 2:** حفظ سجلات النزلاء والإقامات في PostgreSQL، تسجيل دخول فعلي،
  إنشاء حسابات الموظفين من المسؤول، وصلاحيات تعديل تُفحص على الخادم.
- **Sprint 3:** فئات المخزون (المخازن، الكانتين، والثلاجة)، أرصدة الأصناف،
  حركات الوارد والمنصرف، وصلاحيات عرض منفصلة لكل فئة ولكل موظف.
- **Sprint 4:** مخزون الكانتين بأسماء جداول وحقول Access الأصلية، وصلاحية
  كاملة تُمنح لكل موظف على حدة، وسندات الصرف، وسجل إلغاء إداري مع سبب.
- **Sprint 5:** مبيعات نقدية وفواتير النزلاء بجداول وحقول Access الأصلية،
  خصم المخزون المرتبط عند الحفظ، دفعات جزئية لحساب النزيل، وإلغاء إداري مع
  سبب وسجل رد المبالغ.
- **Sprint 6:** دليل أصناف الثلاجة والوارد، مبيعات اللحوم المدفوعة بالكامل،
  تعديل السعر لكل عملية، خصم الكمية من الثلاجة، وإلغاء إداري مع سبب ورد المبلغ.
- **Sprint 7:** ملفات الموظفين بكل حقول Access، دليل الموظفين، وتسجيل الإجازات
  المعتمدة من المسؤول، مع ربط يدوي للحساب وإظهار الملف والإجازات للموظف نفسه فقط.
- **Sprint 8:** أضفنا مخطط Access الأصلي `nam` بكل حقوله، والجداول المرتبطة
  بالنزيل ومفتاح UUID/Access للتوفيق لاحقًا. لا تُزامن شاشة النزلاء الحالية
  هذه الجداول تلقائيًا؛ عرض النزلاء للموظفين يقتصر على الحقول الأساسية حسب
  الصلاحية، والبيانات الحساسة مؤجلة.
- **Sprint 9:** تقارير الفواتير حسب التاريخ والفئة، مع إجماليات يومية وشهرية،
  وتفاصيل قابلة للبحث، وتنزيل CSV، وصفحة طباعة يمكن حفظها PDF من المتصفح.
  يمكن للموظف الحاصل على صلاحية الكانتين عرض فواتير النزلاء والنقدية؛ إنشاء
  الفواتير وإلغاؤها يظل للمسؤول فقط.
- **Sprint 10:** تقرير الإقامة حسب تاريخ الدخول والفيلا والغرفة، يعرض رقم الملف
  والاسم وحالة الإقامة وتاريخي الدخول والخروج والفيلا والغرفة فقط. يتطلب من
  الموظف صلاحية تعديل بيانات النزلاء؛ تُستبعد السجلات المؤرشفة افتراضيًا،
  ويمكن تضمينها صراحةً. يتوفر CSV والطباعة/الحفظ بصيغة PDF من المتصفح.
- **Sprint 11:** تقارير أرصدة الكانتين وحركات الوارد والمنصرف ضمن فترة، مع
  إجماليات الكميات وتفاصيل المستلم وسند الصرف. صلاحية الكانتين مطلوبة؛ الأرصدة
  والإجماليات تستبعد الحركات الملغاة، مع خيار إظهارها للمراجعة وأسباب الإلغاء.
  يتوفر CSV والطباعة/الحفظ بصيغة PDF من المتصفح.
- **Sprint 12:** إضافة مخطط جداول المخزن الثلاثة بأسماء وحقول وأنواع Access
  الأصلية (`الاصناف`, `راس المخزن`, `اطراف المخزن`)؛ أُكمل سير العمل في Sprint 15.
- **Sprint 13:** إضافة مخططي `راس العهدة` و`العهدة` بحقول وأنواع Access
  الأصلية؛ أُكمل سير العمل في Sprint 15.
- **Sprint 14:** إدارة قوائم الكنيسة والمحافظة واليوم وجدول `الفئه` المنفصل
  عن `الفئة`. المسؤول يدير القيم والموظف يعرضها؛ ملف الموظف يستخدم الكنيسة
  والمحافظة/المركز، والفواتير تستخدم `الفئه` بينما يظل اليوم مشتقًا من التاريخ.
  إعادة التسمية تحدّث القيم المرتبطة، ويُمنع حذف قيمة مستخدمة.
- **Sprint 15:** إدارة دليل أصناف المخزن والوارد، وإصدار العهدة لموظف مسجل مع
  خصم المخزون، والإرجاع الجزئي أو الكامل، ونقل الكمية المتبقية لموظف آخر،
  والإلغاء الإداري بسبب مع إعادة المتبقي. الموظف يعرض سجلات عهدته فقط.
  سعر العهدة الافتراضي من دليل المخزن مع إمكانية تعديله؛ الإجمالي محسوب.
  الحركات تُحفظ في سجل تدقيقي ولا تُحذف.
- **Sprint 16:** استخدام قائمة `رقم الفيلا.N_V` في إدخال الإقامات مع الحفاظ على
  القيم التاريخية، وإضافة سجل مالي مستقل للمسؤول باستخدام `راس النزيل` و
  `اطراف النزيل`. تُسجل إيصالات متعددة بمبالغ موجبة وتواريخ تسوية اختيارية؛
  الإلغاء بسبب يحفظ السجل ولا يمثل ردًا نقديًا. لا مزامنة مع النزلاء UUID أو
  `nam` ولا استيراد لسجلات Access.
- خطة التغطية [docs/access-coverage-plan.md](./docs/access-coverage-plan.md)
  تسرد كل جداول Access الـ32 وحقولها، والنماذج والتقارير والاستعلامات، وتوضح
  ترتيب تنفيذ ما لم يُغطَّ بعد. وجود الحقل في الخطة لا يعني أن شاشة الويب أو
  استيراد بياناته قد نُفّذ.
- يحتفظ كل دخول/خروج بسجل إقامة مستقل؛ لا يستبدل الدخول الجديد سجلًا سابقًا.
- لا يوجد تسجيل عام للحسابات. الموظف الجديد يبدأ بصلاحية القراءة، ويمكن للمسؤول
  منحه صلاحية تعديل النزلاء أو صلاحية عرض فئات مخزون محددة. صلاحية الكانتين
  تشمل تقارير مخزون الكانتين وجميع الفواتير، بما فيها فواتير النزلاء والنقدية.
- الموظف لا يرى أي فئة مخزون قبل منحها له. يفرض الخادم هذا التقييد على الأصناف
  والحركات، وليس على واجهة المستخدم فقط. الموظف لا يستطيع إجراء تغييرات مخزون.
- حركات المخزون محفوظة كسجل تاريخي؛ الرصيد الحالي محسوب من الوارد والمنصرف،
  ولا يمكن صرف كمية أكبر من الرصيد. يمكن للمسؤول إلغاء حركة مع الاحتفاظ بها
  كملغاة في سجل المراجعة.
- البيانات الوهمية فقط متاحة في وضع التطوير. حقول الموظفين والصور تحفظ
  كبيانات نصية فقط؛ لا تُرفع ملفات صور. حقول النزلاء الصحية والتأهيلية
  والقومية والدينية ومسارات الصور غير مفعّلة، رغم وجود مخططها في التغطية.

## التشغيل المحلي

```bash
npm install
npm run dev
```

من دون إعداد متغيرات قاعدة البيانات والمصادقة، يعرض التطوير بيانات وهمية مؤقتة.
لا تستخدم بيانات أشخاص حقيقيين في هذا الوضع.

لفحص التغييرات:

```bash
npm run lint
npx tsc --noEmit
npm run build
```

## إعداد Neon والتخزين الدائم

1. أضف Neon من Vercel Marketplace، واختر المنطقة فقط بعد اعتمادها من المركز.
2. انسخ `.env.example` إلى `.env.local`، وضع بيانات الاتصال المحلية في
   `DATABASE_URL`، ومفتاحًا عشوائيًا قويًا في `BETTER_AUTH_SECRET`.
3. اضبط `BETTER_AUTH_URL` على `http://localhost:3000` محليًا. عند النشر، أضف
   عنوان HTTPS الصحيح في متغيرات بيئة Vercel.
4. اضبط `APP_MODE=persistent`، ثم راجع جميع ملفات الترحيل قبل تطبيقها. تنشئ
   الترحيلات جداول التطبيق وفئات المخزون الأولية وجداول Access المنفذة حتى الآن
   بأسمائها الأصلية. لم تُطبّق الترحيلات على قاعدة دائمة، ولم تُستورد أي سجلات
   من Access:

   ```bash
   npm run db:generate
   npm run db:migrate
   ```

5. أنشئ حساب المسؤول الأول من مجلد المشروع. ستتم مطالبتك بكلمة المرور إذا لم
   تمررها كخيار:

   ```bash
   npm run auth:create-admin -- --email admin@example.com --name "مدير النظام" --role admin
   ```

لا تشغّل ترحيلات أو بيانات تجريبية على قاعدة إنتاج قبل مراجعة الإعدادات. لإضافة
سجلات خيالية للاختبار فقط، اضبط `SEED_DEMO_DATA=true` ثم نفّذ
`npm run db:seed-demo` على قاعدة تطوير منفصلة.

## النشر والخصوصية

المشروع مهيأ للنشر على Vercel، لكن لم يتم نشره أو ربطه بقاعدة حية. لا تستورد
قاعدة Access ولا تدخل بيانات حقيقية قبل اعتماد منطقة الاستضافة، وسياسة الخصوصية،
ومدة الاحتفاظ بالبيانات، وخطة النسخ الاحتياطي والاستعادة.

ملف Access الاحتياطي لا ينتمي إلى المستودع. قواعد Git تستثني ملفات Access
وقواعد البيانات المحلية وملفات الأسرار.
